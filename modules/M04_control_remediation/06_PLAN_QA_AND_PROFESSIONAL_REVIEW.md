# 計畫品質檢查與專業審查

## 1. 文件品質檢查
- 章節完整、編號一致、圖表可追溯。
- 場址名稱、地址、地號、座標、面積及污染物前後一致。
- 所有濃度、目標、單位、日期與分析方法一致。
- 圖面具有圖例、比例尺、指北針、座標系統、來源與日期。
- 每項事實性敘述具資料來源或明確標示推論。
- 所有引用可回溯至文件、資料集、版本或快照。
- 資料缺口、限制、假設及不確定性未被隱藏。

## 2. 技術一致性檢查
- 污染範圍與採樣資料一致。
- 概念場址模式涵蓋來源、介質、傳輸途徑與受體。
- 工法與污染物、相態、地層及水文地質相容。
- 設計能力與處理量、污染量、操作期程相符。
- 監測點位與控制邊界、羽流及受體相符。
- 成本與期程引用相同設計基準。
- 應變條件可由監測資料實際判定。

## 3. AI內容檢查
- 不得虛構法規、主管機關意見、污染數據或案例。
- 不得將候選產業污染物寫成場址已確認污染物。
- 不得將背景值、管制標準、整治目標與實測值混用。
- 不得保證工法成效、成本或解除列管。
- 每段生成內容保存Prompt版本、模型、證據集合、輸出時間與人工修改紀錄。
- 無可靠證據時輸出「資料不足／待確認」，不得補寫確定結論。

## 4. 專業審核角色
- 編製者：整理資料與撰寫草稿。
- 環境專業審查者：污染、水文地質、採樣、工法與監測。
- 法規審查者：適用程序、法規版本與主管機關要求。
- 成本／工程審查者：數量、單價、施工性、工期與風險。
- 核准者／簽證者：依其法定或契約責任完成最終核准。

同一人兼任時須符合組織政策並保留利益衝突說明。

## 5. 審查關卡
`draft` → `technical_review` → `legal_review` → `cost_schedule_review` → `client_review` → `approved_for_submission` → `submitted` → `authority_revision` → `approved`。

每次狀態轉換保存：版本、審查人、日期、意見、處理結果、未結事項與附件。

## 6. 發布阻擋條件
- 缺少污染範圍或關鍵設計資料卻未揭露。
- 法規或指引版本未確認。
- 重要圖表、監測、應變、成本或期程章節缺漏。
- 存在未處理的高風險審查意見。
- 引用來源失效或無法追溯。
- AI生成內容尚未完成指定人工審核。
